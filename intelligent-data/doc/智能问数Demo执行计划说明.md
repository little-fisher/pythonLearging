# 智能问数 Demo 执行计划说明

## 一、任务背景

本周计划基于现有智能问数相关文档、数据库脚本和演示页面，使用小艾智能体或 Dify 配置并跑通一个智能问数 Demo。

本次任务的重点不是完全依赖 AI 自动完成开发，而是通过阅读技术方案、确认业务口径、配置智能体工作流和实际联调，熟悉智能问数从自然语言提问到数据查询、图表生成、结果展示及历史留存的完整链路。

结合现有项目已经接入小艾平台工作流的情况，本次优先使用小艾智能体实现；如果小艾平台暂时无法提供测试工作流或数据库工具，再使用 Dify 完成同等流程验证。

## 二、任务目标

本周完成一个可演示的智能问数最小闭环：

```text
用户自然语言提问
→ 智能体识别查询意图
→ 获取数据库表和字段信息
→ 生成安全的只读 SQL
→ 执行 SQL 查询
→ 整理查询结果
→ 推荐图表类型
→ 生成总结和 HTML 报表
→ 返回页面展示并保存历史
```

计划优先验证以下演示问题：

> 展示全国近一个月 65 岁以上老年人死亡数最高的 3 个死因。

最终 Demo 应至少达到以下效果：

1. 用户可以通过自然语言提交查询问题。
2. 智能体能够识别时间、地区、年龄、指标和排名条件。
3. 能够根据真实数据库结构生成 SQL。
4. SQL 经过安全校验后才允许执行。
5. 查询结果能够生成总结文字和图表。
6. 最终结果能够在页面或工作流调试界面中展示。
7. 能够查看关键节点的输入、输出和错误信息。

## 三、实施原则

- 不让 AI 全程自动完成，关键配置由本人操作。
- AI 可以辅助生成提示词、节点说明、SQL 校验规则和操作步骤。
- 业务指标、统计口径和字段映射不由 AI 猜测，必须由业务人员确认。
- SQL 必须使用只读数据库账号执行。
- 不把数据库密码、平台密码和 API Key 写入前端或代码。
- 优先实现一条可验证的纵向链路，不在第一阶段扩展复杂功能。
- 先保证查询结果正确，再增加图表和页面效果。
- 本周不以支持所有自然语言问题为目标，只保证选定演示问题可以稳定运行。

## 五、整体技术链路

### 5.1 用户提交问题

用户在智能问数页面输入自然语言问题，前端调用：

```http
POST /api/intelligent-data/stream
```

请求示例：

```json
{
  "question": "展示全国近一个月65岁以上老年人死亡数最高的3个死因",
  "session_id": ""
}
```

Python 后端收到问题后，调用小艾平台的智能体工作流，并通过 SSE 将工作流执行状态转发给前端。

### 5.2 查询意图识别

工作流首先将用户问题转换成结构化查询条件，预期输出如下：

```json
{
  "status": "success",
  "metric": "死亡人数",
  "time_range": "近一个月",
  "region": "全国",
  "filters": [
    {
      "field": "年龄",
      "operator": ">=",
      "value": 65
    }
  ],
  "group_by": ["死因"],
  "order": "死亡人数降序",
  "limit": 3,
  "normalized_question": "统计全国近一个月65岁及以上人群的死亡人数，按死因分组并取前三名"
}
```

如果时间、地区或统计口径无法确定，应返回 `clarification_required`，不能直接猜测并生成 SQL。

### 5.3 读取数据库元数据

通过数据库元数据工具读取授权范围内的表名、表注释、字段名、字段类型和字段注释。

预期输出：

```json
{
  "tables": [
    {
      "name": "业务表名称",
      "comment": "业务表说明",
      "columns": [
        {
          "name": "字段名称",
          "type": "字段类型",
          "comment": "字段业务含义"
        }
      ]
    }
  ],
  "schema_ddl": "供大模型生成SQL使用的简化表结构"
}
```

第一版只读取本次场景涉及的表或视图，不把整个数据库的所有表结构都传给模型。

### 5.4 生成 SQL

NL2SQL 节点接收用户问题、结构化查询条件、数据库结构和业务口径，输出：

```json
{
  "status": "success",
  "sql": "SELECT ...",
  "used_tables": ["授权表"],
  "used_columns": ["授权字段"],
  "explanation": "SQL统计逻辑说明"
}
```

生成规则：

- 只能生成 `SELECT` 查询。
- 只能使用授权表和字段。
- 必须包含逻辑删除条件。
- 必须包含租户隔离条件。
- 不查询姓名、电话、身份证和详细地址等敏感字段。
- 必须设置 `LIMIT`。
- 不允许编造表名或字段名。
- 不确定业务口径时返回澄清提示。

### 5.5 SQL 安全校验

SQL 在执行前必须经过程序校验，不能只依赖大模型提示词。检查内容包括：

1. 是否只有一条 SQL。
2. 是否为只读查询。
3. 是否包含增删改或 DDL 危险关键字。
4. 是否只使用授权表和字段。
5. 是否查询敏感字段。
6. 是否遗漏逻辑删除条件。
7. 是否遗漏租户隔离条件。
8. 是否包含返回数量限制。
9. 是否可能造成无约束的全表扫描。
10. 是否设置查询超时。

校验不通过时返回明确错误，不允许执行 SQL。

### 5.6 执行 SQL 与自动纠错

SQL 校验通过后，使用只读数据库账号执行。执行成功时返回字段、数据和行数。

如果执行失败，将用户问题、上一次 SQL、数据库错误和真实数据库结构交回 NL2SQL 节点进行修正，最多自动重试两次。超过重试次数后终止流程并返回错误原因。

### 5.7 图表推荐

根据查询结果的数据结构推荐图表：

- 时间趋势使用折线图。
- 分类对比使用柱状图。
- 占比分析使用饼图。
- 明细数据使用表格。
- Top N 排名优先使用横向柱状图。

本场景预期输出：

```json
{
  "charts": [
    {
      "type": "bar",
      "direction": "horizontal",
      "title": "近一个月65岁以上人群死亡数最高的3个死因",
      "dimension": "死因",
      "measures": ["死亡人数"]
    }
  ],
  "summary": "根据查询结果生成的总结性文字"
}
```

### 5.8 生成 HTML 报表

使用固定 HTML 模板和 ECharts 渲染报表，报表至少包括：

- 报告标题。
- 用户原始问题。
- 查询条件。
- 总结性文字。
- 图表。
- 数据明细表。
- 数据来源和统计口径。
- 生成时间。
- AI 分析免责声明。

AI 只生成结构化图表配置和总结文字，HTML 页面由固定程序模板渲染，避免让模型自由生成完整页面。

工作流最终输出建议统一为：

```json
{
  "status": "success",
  "title": "报告标题",
  "summary": "分析结论",
  "sql_statement": "实际执行的SQL",
  "used_tables": ["使用的数据表"],
  "row_count": 3,
  "html_content": "<html>...</html>",
  "html_url": "",
  "files": []
}
```

### 5.9 前端展示与历史记录

工作流通过 SSE 返回以下事件：

```text
node_start
node_complete
workflow_complete
```

前端展示当前执行节点、最终总结、图表和下载文件。后端同时保存会话编号、用户问题、执行步骤、最终结果和 HTML/PDF 地址，供历史记录回放。

## 九、风险及应对措施

### 9.1 业务口径不明确

风险：模型可以生成 SQL，但统计结果不可信。

应对：先由业务人员确认口径，再配置提示词和字段映射；无法确认时不允许模型猜测。

### 9.2 数据表数量过多

风险：一次传入所有表结构，容易超出上下文并选错表。

应对：第一版只授权当前场景涉及的表，条件允许时建立专用业务视图。

### 9.3 SQL 存在安全风险

风险：模型生成增删改语句或查询敏感字段。

应对：使用只读数据库账号，并增加独立的程序安全校验，不只依赖提示词。

### 9.4 AI 生成结果不稳定

风险：同一个问题多次生成不同 SQL。

应对：补充字段注释、业务词典、固定 JSON 输出、正确示例，并适当降低模型随机性。

### 9.5 工作流结果无法被前端识别

风险：工作流执行成功，但返回字段与页面约定不一致。

应对：统一最终结果结构，至少返回 `status`、`summary`、`sql_statement`、`row_count` 和 `html_content` 或 `html_url`。

### 9.6 HTML 图表无法展示

风险：查询字段与图表配置不一致，导致 ECharts 无法渲染。

应对：AI 只生成受约束的图表 JSON，由固定模板完成渲染，并校验维度、度量字段是否存在。
