# Playwright 验证方法

Playwright 用于真实浏览器验证。优先验证窄流程，不把每次任务都扩展成完整端到端测试。

如使用 Playwright MCP，仍按本文档记录证据：MCP 负责打开页面、截图、监听 console/network；Harness 只接受写入 evidence 的事实，不把“工具跑过”当成通过。

## 标准检查

- 打开目标路由。
- 等待根视图或关键文本出现。
- 确认触发入口可见。
- 点击触发入口。
- 确认弹窗、面板、表格或 tooltip 出现。
- 视觉布局重要时截屏。
- 检查 console error 和失败网络请求。
- 涉及接口时记录关键请求状态码和响应字段摘要。
- 涉及 Figma、设计规范或参考截图时，记录设计来源、实际截图和差异说明。

## 建议记录的证据

- 路由 URL。
- viewport 尺寸。
- 点击的触发入口。
- 期望 selector 或文本。
- 截图路径。
- console 或 network 错误。
- 关键接口状态码、请求方法和响应摘要。
- Figma URL、设计规范文件或参考截图来源。
- trace、video 或 HAR 路径（如果有）。

## 页面绘制与设计比对

页面绘制、视觉还原、Figma 链接、设计规范类任务，优先按以下闭环：

1. 打开真实页面。
2. 截取目标 viewport。
3. 与 Figma 截图、设计规范或参考图比对。
4. 修正页面。
5. 再次截图比对，直到差异可解释或达到用户验收边界。

复杂页面任务应把截图路径写入 QA Gate evidence，不能只写“页面已检查”。

## Network 与接口核验

涉及后端接口、前端请求、数据加载或 TS/API 契约时：

- 记录关键接口 URL、method、status。
- 记录响应中与本任务相关的字段摘要。
- 对照 TS 类型、OpenAPI、Swagger、DTO、schema 或后端定义。
- console 报错、请求 4xx/5xx、CORS、字段缺失、类型不一致，都不能作为 pass 关闭。

## 地图与 Canvas 边界

Playwright 能证明地图路由加载、图层入口存在、UI 状态变化；不能完全证明 canvas 内地理形状业务正确。地图重任务应组合：

- Playwright 截图。
- 数据或资源路径验证。
- CodeGraph 清理链路验证。
- 依赖形状和位置判断时的人工视觉确认。

## 资源边界

PDF、图片、JSON、txt 等资源任务不能只验证“按钮能点击”。如果需求依赖数据内容，需要结合 Node 解析、路径检查或资源状态检查。
