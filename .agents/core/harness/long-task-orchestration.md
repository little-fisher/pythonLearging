# 长任务与多 Agent 编排

本文档用于处理跨多轮、跨阶段或需要多个 Agent 接手的任务。目标是把长任务切成可交接的阶段，而不是让单轮上下文无限膨胀。

## 启用条件

- 用户要求分阶段执行、长期推进或后续接手。
- 当前任务预计需要多次实现-验证循环。
- 任务涉及多个 owner、多个验证环境或多个独立子目标。
- 单轮上下文预算会超过 `core/harness/cost-budget.md` 的 `complex` 上限。

## 编排角色

- Orchestrator：维护目标、阶段、范围、预算和交接。
- Generator：按当前阶段契约做最小实现。
- Evaluator：按契约和证据独立判断结果。
- Researcher：只在需要外部资料、竞品、规范或未知工具时使用。

同一任务不要默认并行多个 Agent。只有子任务相互独立、上下文不冲突、验证边界清楚时才并行。

## 阶段结构

每个阶段都要有：

- 阶段目标。
- 范围内和范围外。
- 输入上下文包。
- 必需成功标准。
- 验证方式。
- 交接记录。
- 预算和停止条件。

长任务记录优先放在 `.agents/project/runs/<task-id>/`，当前阶段摘要同步到 `.agents/project/memory/current/`。

## 停止条件

- 关键产品决策、权限或素材缺失。
- 当前阶段验证失败且无法通过局部返工解决。
- 子 Agent 产物冲突，无法判断应保留哪个方向。
- 继续推进会超过预算且没有明确收益。
