# 成本与 Token 预算

本文档用于控制任务前置阅读、工具调用和验证范围，避免把小任务做成长任务。

## 默认预算

| 等级 | 建议上下文预算 | 最大文档数 | 默认动作 |
| --- | ---: | ---: | --- |
| `micro` | 3k tokens | 4 | 直接处理，窄验证 |
| `normal` | 8k tokens | 8 | 上下文包，窄验证 |
| `complex` | 16k tokens | 12 | 契约、memory、Evaluator |
| `long` | 24k tokens/阶段 | 14 | 阶段化编排和交接 |

预算是上限，不是必须用满。实际任务优先读取更少、更近、更相关的材料。

## 成本闸口

- 不因为有工具就运行全量验证。
- 不因为有通用模板就同时读取通用模板和项目实例。
- 不把历史 memory 全量注入，只取当前任务相关事实。
- CodeGraph、Playwright、build 等重工具只在任务风险匹配时使用。
- 全量 build、长 trace、大截图集和多 Agent 并行需要明确收益。

## 预算升级

允许升级预算的情况：

- 初始上下文不能定位 owner 或影响面。
- 验证失败暴露出跨模块根因。
- 用户明确要求回归、评审、长期执行或多 Agent 接手。
- 任务涉及公开接口、数据生成链路、地图/canvas 或生产发布风险。

## 预算降级

允许降级预算的情况：

- 命中复杂关键词，但实际只改静态文案、配置或单文件。
- 项目覆盖配置已经给出明确 owner 和验证方式。
- 相关源码锚点能直接证明影响面很窄。

降级时在上下文包或最终回复中说明依据。
