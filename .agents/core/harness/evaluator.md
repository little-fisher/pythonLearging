# Evaluator 工作流

Evaluator 是独立评审角色，用于检查 Generator 的产物是否满足任务契约。它的目标不是重写实现，而是发现偏离需求、验证不足、回归风险和质量退化。

## 使用时机

以下情况默认启用 Evaluator：

- 已创建 `task-contract.json` 的任务。
- 跨模块、跨状态、地图/canvas、数据链路或运行时交互任务。
- 用户要求“检查”“评审”“回归”或“确认没有破坏”。
- 实现过程中出现失败验证、方案变更或风险升级。

## 输入材料

Evaluator 至少读取：

- 任务契约：`core/templates/task-contract.json` 的实例。
- 本次 diff 或改动文件列表。
- 相关 `AGENTS.md`、任务路由、项目规则和完成定义。
- 已执行验证的命令输出、截图路径、日志或手工说明。

## 评估维度

| 维度 | 通过标准 |
| --- | --- |
| 需求符合度 | 所有必需成功标准都有对应实现和证据。 |
| 功能正确性 | 目标行为在真实或等价环境中可复现。 |
| 回归风险 | 受影响路径已做最小合理回归检查。 |
| 代码/文档质量 | 没有无关重构、过度抽象、路径漂移或规则冲突。 |
| 证据完整性 | 已验证、未验证、风险和人工边界清楚。 |

## 硬失败条件

出现任一情况，结论必须为 `fail`：

- 必需成功标准没有证据。
- 实现后静默修改契约来匹配结果。
- 有阻塞运行时错误、明显 console error 或核心路径不可用。
- 只做静态阅读，没有执行契约要求的可行验证。
- 改动越过明确的 `scope.out` 或项目红线。
- 剩余风险会影响用户核心目标，但未请求确认。

## 输出

使用 `core/templates/evaluator-report.md`。结论只能是：

- `pass`：必需标准已满足，剩余风险不阻塞。
- `fail`：存在必须返工的问题。
- `blocked`：缺少用户决策、权限、素材或外部环境，无法继续验证。

## 与 Generator 的关系

- Evaluator 给出可执行反馈，不直接扩大实现范围。
- 返工项应引用具体成功标准、文件、命令或证据。
- 如果只是主观偏好或非本次问题，应放入风险，不作为失败项。
