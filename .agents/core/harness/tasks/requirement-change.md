# 任务：需求修改

当需求改变已有行为、规则、布局、数据展示或业务约束时使用。

## 先读

1. `.agents/project/charter.md`
2. 相关领域文档
3. 已存在的相关模块 playbook

## 执行原则

- 修改前先找到当前规则的控制路径。
- 改 owning 实现，不在多个表面叠补丁。
- 除非需求明确改变，保留现有公开行为和目录结构。
- 仓库级规则变化时，同步更新对应 `.agents/` 文档。

## 检查清单

- 当前规则在哪里实现？
- 是否有父组件、watcher 或调用方依赖这条规则？
- 是否同时影响资源、数据或路由？
- 需求是局部调整，还是重新定义项目规则？
- 是否有足够窄的验证方式证明新规则生效？
