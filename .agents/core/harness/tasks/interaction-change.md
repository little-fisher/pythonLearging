# 任务：新增或修改交互

当需求涉及点击行为、弹窗行为、状态切换、详情展开、轮播、跨面板联动或地图触发时使用。

## 先读

1. `.agents/project/charter.md`
2. `.agents/project/architecture/state-boundaries.md`
3. 项目覆盖层中声明的相关交互、弹窗、详情或状态领域文档
4. 相关模块文档

## 执行原则

- 先判断交互状态的 owner。
- UI 局部状态默认留在所属组件内。
- 优先复用当前弹窗、详情和 watcher 路径。
- 追踪详情退出、模块切换和组件卸载时的清理行为。

## 检查清单

- 哪个组件或视图拥有这个交互？
- 该状态是否真的需要 Pinia？
- 交互关闭或切换后是否残留弹窗、高亮或选中态？
- 地图、路由或页面副作用是否走现有 watcher/effect 路径？
- 是否保留了当前 UI 层级和行为契约？
