# 任务：测试回归

当需求是确认近期改动是否破坏已有行为时使用。

## 先读

1. `.agents/project/charter.md`
2. 与改动区域匹配的任务文档
3. 相关领域或模块文档

## 执行原则

- 从改动范围推导最小合理回归面。
- 优先检查最容易受共享状态、watcher 或复用 UI 影响的流程。
- 使用窄范围 walkthrough，不默认全项目验证。
- 除非用户明确要求，不以 build 作为默认回归方式。

## 检查清单

- 哪个路由、模块或 watcher 路径最容易回归？
- 改动是否影响共享 store 或共享弹窗？
- 首页与地图的协调路径是否仍成立？
- 终端是否存在与改动区域相关的错误？
- 无法自动验证的风险是否已明确说明？
