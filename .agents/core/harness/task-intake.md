# 任务入口分级

本文档用于把自然语言任务先分成 `micro`、`normal`、`complex`、`long` 四档，再决定是否生成上下文包、创建任务契约、写入实时记忆或启用 Evaluator。

## 默认入口

优先运行：

```bash
node .agents/scripts/agent-context-pack.mjs --task "用户原始需求"
```

脚本会输出任务类型、任务大小、建议阅读文档、预算和执行闸口。脚本不可用时，按本文档手工判断。

## 分级标准

| 等级 | 适用任务 | 必需动作 | 禁止扩大 |
| --- | --- | --- | --- |
| `micro` | 单文件文案、格式、静态说明、小配置 | 只读入口和直接相关文件，说明验证方式 | 不建契约，不写 memory，不启用 Evaluator |
| `normal` | 单功能改动、窄交互、普通 bug、局部数据更新 | 生成上下文包，做窄验证；必要时记录建议 QA Gate | 不默认全量 build，不默认多 Agent |
| `complex` | 跨模块、跨状态、地图/canvas、公开接口、数据生成链路、页面绘制、Figma/设计还原、接口契约 | 上下文包、任务契约、实时记忆、QA Gate、Evaluator | 不在无证据时扩大到全项目验证 |
| `long` | 多阶段、跨多轮、多人/多 Agent 接手、路线图落地 | long task 编排、分阶段契约、QA Gate、交接记录、Evaluator | 不把所有阶段一次性塞进当前上下文 |

## 闸口规则

- `micro`：目标和验证方式能在最终回复中说清即可。
- `normal`：需要明确范围、受影响文件和验证命令；QA Gate 默认建议不阻断，失败后再升级为 `complex`。
- `complex`：必须创建或更新任务契约，并记录必要事实到 `.agents/project/memory/current/`；命中 UI、Figma、network、API/TS 契约时必须登记 QA Gate。
- `long`：必须拆阶段；每阶段只保留当前需要的上下文，其余写入 runs 或交接记录；阶段验收按 QA Gate 和 Evaluator 收口。

## 升级条件

出现以下任一情况，任务至少升级到 `complex`：

- 需要超过一次实现-验证循环。
- 影响跨模块状态、路由、数据生成链路或公开接口。
- 自动验证失败且需要改变方案。
- 用户要求后续 Agent 接手、长期执行、回归确认或独立评估。
- 页面绘制需要按设计规范、Figma 链接或参考截图反复比对。
- 接口、network、状态码、返回内容或 TS/API 契约是验收条件。

## 降级条件

如果任务虽然命中复杂关键词，但实际只改一个低风险文件，可以降级到 `normal`。降级时要在回复或上下文包中说明理由。
