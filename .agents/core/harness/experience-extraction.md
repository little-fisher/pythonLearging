# 经验抽取

经验抽取用于在任务完成后，把可复用结论沉淀为规则、playbook、模板或 skill 候选，而不是把聊天记录当知识库。

## 使用时机

以下任务结束前需要做经验抽取：

- `complex` 或 `long` 任务。
- 出现失败验证、返工、工具限制或方案切换。
- 同类问题第二次出现。
- 用户明确要求沉淀流程、规则、模板或复盘。

`micro` 任务默认不抽取经验。

## 抽取内容

只保留能复用的内容：

- 触发条件：什么任务或现象下适用。
- 有效做法：最终证明可行的步骤或判断。
- 失败模式：不要再重复的路径。
- 验证证据：能证明结论的命令、截图、日志或人工边界。
- 沉淀位置：项目规则、当前 memory、playbook、模板或独立 skill。

## 写入规则

- 项目专属经验写入 `.agents/project/`。
- 当前任务事实写入 `.agents/project/memory/current/`，结束前压缩。
- 重复流程优先写成项目 playbook 或模板；跨项目稳定后再考虑 skill。
- 不把一次性排查日志、长命令输出或未验证猜测写成规则。

## 输出格式

可使用 `core/templates/experience-report.md`。如果没有必要新建文件，最终回复中简要说明“不沉淀”的原因即可。
