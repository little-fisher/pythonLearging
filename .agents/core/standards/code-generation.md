# 代码生成规范

生成或修改代码时使用本文档。项目已有结构优先于外部通用风格指南。

## 规则来源

1. 用户明确需求。
2. 仓库现有实现、命名、目录和调用方式。
3. `.agents/project/` 中的项目专属规则。
4. `.agents/core/` 中的通用规范。
5. 外部最佳实践只作为辅助，不覆盖本仓库约定。

## 模块边界

- 页面或路由视图负责布局、路由状态和拥有的子组件协调。
- 展示组件负责 UI 渲染和本地交互状态。
- 工具函数负责纯计算或小范围数据整理。
- composable 或 helper 只有在复用和生命周期收益明确时才新增。
- 共享状态只用于跨页面、跨模块或跨表面协调。

## 抽象规则

只有满足以下至少一条时才新增抽象：

- 两个以上真实调用点需要同一行为。
- 业务概念稳定且会复用。
- 抽象能避免生命周期、清理或数据契约错误。
- 仓库已有相同风格的本地模式。

不要为了“看起来工程化”而新增抽象类、注册表或框架层。

## 数据契约

新增 JSON、txt、PDF、图片或表格数据能力时：

- 在第一个数据适配点附近说明关键字段语义。
- 对缺失、空数据和格式异常使用保守兜底。
- 数据转换脚本和消费代码保持同步。
- 不把数据解析逻辑散落在多个 UI 表面。

## 最小修改

只改完成需求所需的最小范围。发现无关问题时记录风险，不顺手重构。
