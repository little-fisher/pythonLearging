# 注释与字段规范

新增或实质修改实现面时使用中文语义注释。注释要解释业务含义、字段用途或生命周期原因，不写机械描述。

## 必须注释的新增内容

- 组件
- 方法和函数
- 关键中间变量
- 配置字段
- store 字段
- 事件 payload 字段
- 数据适配后的字段
- 地图图层、弹窗、表格列和资源入口

## 函数注释格式

每个新增方法或函数使用结构化注释，参数名必须和实现保持一致。

```js
/**
 * 根据站点坐标计算弹窗锚点，避免弹窗超出中心区域。
 * @param station - 站点原始数据。
 * @param bounds - 中心区域可用边界。
 * @returns 修正后的弹窗锚点坐标。
 */
function resolvePopupAnchor(station, bounds) {
  return station;
}
```

没有参数时仍保留 `@returns`。没有有意义返回值时写 `@returns 无返回值。`

## 字段注释格式

新增字段在首次声明处说明语义。

```js
const reportRows = [
  {
    /** 预报单展示名称，用于表格首列和弹窗标题。 */
    name: '风暴潮预报单',
    /** 预览资源路径，交给已有 PDF 预览 helper 打开。 */
    url: '/static/pdf/report.pdf'
  }
];
```

## 不要写的注释

- “设置值”
- “返回结果”
- “点击事件”
- 和变量名完全重复的翻译
- 为未修改的旧代码批量补注释

## 范围边界

只给新增或实质修改的代码补注释。不要把一次业务改动扩展成全文件注释整理。
